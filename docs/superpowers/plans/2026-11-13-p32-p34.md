# P32 to P34 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox
> (`- [ ]`) syntax for tracking.

**Goal:** build the night's second round (P32, P33, P34) in three parallel lanes and measure each against the night's
candidate `p30_w030` on the DFL benchmark, so that Tian can decide in the morning.

**Architecture:** each lane adds an off-by-default capability (a new evidence source, a feature version, a training
option), its artifact and its configs; the controller trains, gates and benchmarks on the main checkout, one heavy run
at a time. This plan continues [the night's first plan](2026-11-12-p29-p31.md): its Global Constraints, Review Focus,
heavy-run protocol and the lanes' constraints file (`constraints.md` in the night's workspace) hold here too.

**Tech Stack:** Python 3.11.9, numpy 2.4.6, scikit-learn as pinned (`requirements-benchmark.txt`), the repository's
own harnesses (`pipeline/selftest.py`, `pipeline/benchmark/selftest.py`).

**Spec:** [2026-11-13-p32-p34-design.md](../specs/2026-11-13-p32-p34-design.md)

## Global Constraints

- Everything of the first plan's Global Constraints. In particular: every new parameter defaults to today's behaviour;
  `main.toml`'s file keeps sha256 `2dd51320b1d32f8be6d06e63f833e6d8e196ddcaad294b606db3914c351c1660`; no lane reads
  `data/`, `evaluation/gt/` or `evaluation/results/`; checks are synthetic; no AI attribution in commits.
- The reference of every benchmark run is `pipeline/benchmark/configs/p30/p30_w030.toml`, which must reproduce raw
  0.5629 and coarse 0.5901 in every run.
- Benchmark settings: `--profile generic --seeds 3 --truth both`. Bar: mean +0.005, sign-flip p ≤ 0.05, neither truth
  below −0.005, through `pipeline/benchmark/p29_bar.py` (`pick` takes the stems in tie-break order).
- New checks in `pipeline/selftest.py` go directly after the existing checks of the same component (`test_shape_features_*`
  for P33; P32's team checks directly after the last `test_shape_possession_*` check); benchmark checks in the lane's
  registered stub (`checks/team.py`, `checks/p33.py`, `checks/p34.py`); no lane edits `checks/__init__.py`.
- Lanes: `../BarcaHackathon-p32` (`lane-p32`), `../BarcaHackathon-p33` (`lane-p33`), `../BarcaHackathon-p34`
  (`lane-p34`), all cut from the commit that adds this plan.

## Review Focus

1. **Versions 1 and 2 of the shape features bit for bit** under version 3 (P33), and today's shape trainer byte for
   byte under `--labels raw` (P34): `train_shape.py --verify` must still pass, `main.toml`'s sha256 and `p30_w030`'s
   scores must not move.
2. **A fold that saw its own match** (P32): every benchmark match is scored by the team model built without it.
3. **The mirror** (P32, P33, P34): `swap` exact for every width (26, 42, 60; P32's 72), the cross and diff columns
   negated and nothing else, the weights carried by the mirrored rows (P34).
4. **The coarse labels** (P34): built by the benchmark's own `truth.coarse_codes` on the same frames, never from the
   features; rows only on frames alive in both truths.
5. **P32's restored code against today's tree:** no Calibration for `generic`, the touch rule frozen as today's
   `main.toml`'s (1.5 m / 6.0 m/s / 1 frame / duel 1.0), the feasibility's decoded comparator read from the config it
   is given (`p30_w030`).

**Interfaces:**
- Consumes: today's `shape_features` (`VERSIONS`, `feature_names`, `columns`, `features(inputs, version)`, `swap`,

- Produces:
  - `VERSIONS = (1, 2, 3)`; `TEAM_COLUMNS_V3 = TEAM_COLUMNS_V2 + ("spread_past_5s", "spread_fut_5s", "width_past_5s",
    "width_fut_5s", "adv_past_20s", "adv_fut_20s")` (26 a team); `CROSS_COLUMNS_V3 = CROSS_COLUMNS +

    to the team's `spread` and `width` columns, `adv_*_20s` to `adv_mean`. Each `_diff` is the `h_` column minus the
    `a_` column of the same one-sided change.
  - `swap` accepts 26, 42 or 60 columns: the two team blocks trade places and every cross column is negated (the
    version's own cross columns: 2 for versions 1 and 2, 8 for version 3). Other widths: `ValueError` as today.
  - `train_shape.DEFAULT_MODEL_PATHS[3] = "pipeline/models/shape_possession_v3_hgb.json"`; `--features` already takes
    its choices from `VERSIONS`.
  - Configs: `p30_w030.toml` with the shape table's `model = "pipeline/models/shape_possession_v3_hgb.json"` and
    `weight` 0.3 (`p33_w030`) or 0.45 (`p33_w045`), each with its own `description`.
